# Project structure and how a change flows through it

Where every file lives, why it lives there, and the exact sequence to follow
when adding something. This is the *operational* companion to
[ARCHITECTURE.md](ARCHITECTURE.md) — that document states the principles (the 4
sources of truth, the layer patterns and their trade-offs), this one is the map
and the step-by-step.

Working rules for AI agents (CodeGraph, languages, quality gates, git flow) are
in [AGENTS.md](../../AGENTS.md). Project status is in
[TASKS.md](../roadmap/TASKS.md).

---

```
commander-companion/
├── AGENTS.md              # how agents work here
├── README.md              # entry point for humans + documentation hub (§8)
├── docker-compose.yml     # db + api + web, full stack locally
├── .gitattributes         # line endings (LF everywhere, CRLF for .bat/.cmd)
├── .githooks/pre-push     # runs the CI checks locally, in Docker
├── .github/
│   ├── workflows/         # backend-ci, android-ci, web-ci, docs-ci, labeler
│   ├── scripts/           # check-i18n-{web,android}.mjs, check-dbml-matches-migrations.sh
│   ├── labeler.yml        # PR labels by changed path
│   └── dependabot.yml     # weekly, majors only
├── backend/               # Go API — owns all real state
├── android/               # Kotlin/Compose client — at the table
├── web/                   # Nuxt 4 client — desktop
└── docs/                  # sources of truth + roadmap + decisions
```

Three deployables, one contract. `android/` and `web/` **never** import from
each other; the only thing they share is [`docs/api/openapi.yaml`](../api/openapi.yaml).

## 2. Backend (`backend/`)

```
backend/
├── cmd/api/
│   ├── main.go          # config → migrations → pool → Fiber → registerModules() → listen
│   └── listener.go      # TCP listener with TCP_NODELAY
├── internal/
│   ├── <feature>/       # one vertical slice per feature — see §2.1
│   ├── common/          # cross-cutting: errors, context keys, DB, health,
│   │                    #   migrations, pagination, tokens, uuid
│   ├── config/          # env loading and validation (config.Load)
│   ├── email/           # Resend client (logs the link to console without an API key)
│   ├── moxfield/        # external Moxfield HTTP client (+ retry)
│   ├── websocket/       # hub, clients, broadcaster, envelope — live game sync
│   ├── sync/            # sync service (no queries of its own)
│   └── testutil/        # test helpers: throwaway DB, fake mailer
├── migrations/          # goose, 000NN_snake_case.sql, sequential and immutable
├── sqlc.yaml            # one entry per slice with a query.sql
├── Makefile             # the commands you should actually use
├── Dockerfile           # linted by hadolint in CI
└── .env.example         # every variable the backend reads
```

### 2.1 Anatomy of a slice

Every feature package under `internal/` has the same shape. `admin`, `auth`,
`decks`, `deckresync`, `friends`, `game-actions`, `games`, `moxfieldimport`,
`playgroups`, `statistics`, `tournaments`, `users` all follow it:

| File | Written by | Role |
|---|---|---|
| `query.sql` | **you** | The SQL, with `-- name: X :one/:many/:exec` annotations. The input to sqlc. |
| `query.sql.go` | **sqlc** | Typed methods generated from `query.sql`. |
| `querier.go` | **sqlc** | The `Querier` interface (`emit_interface: true`). |
| `models.go` | **sqlc** | Row structs mapped from the schema. |
| `db.go` | **sqlc** | `DBTX`, `Queries`, `New`, `WithTx`. |
| `dto.go` | **you** | Request/response payloads of the HTTP contract. |
| `service.go` | **you** | Business logic. Takes `*pgxpool.Pool`, works in `pgtype` types. |
| `handler.go` | **you** | Fiber transport + `RegisterRoutes`. |
| `service_test.go` | **you** | Tests; most need a real Postgres (`internal/testutil`). |

**The four sqlc files carry `// Code generated by sqlc. DO NOT EDIT.` — never
touch them by hand.** Change `query.sql`, run `make generate-sql`, commit the
result. CI fails if `sqlc generate` produces any diff.

Some slices add a file for logic that isn't transport, persistence, or plain
service code — `auth/token.go`, `auth/google.go`, `auth/middleware.go`,
`tournaments/pairing.go`, `statistics/dashboard.go`. That is fine: extra
purpose-named files, never a new layer.

### 2.2 The three layers, and where the real boundary is

```
HTTP  →  Handler  →  Service  →  Queries (sqlc)  →  PostgreSQL
```

- **Handler** knows nothing about SQL. It parses the body, reads the user id
  from `c.Locals(common.UserIDKey)`, calls the service, and maps errors through
  `common.MapError`. This is the layer that is genuinely decoupled.
- **Service** is *deliberately not* infrastructure-free: it takes
  `*pgxpool.Pool` (to open transactions) and speaks `pgtype.UUID`,
  `pgtype.Text`, `pgx.ErrNoRows`. Documented trade-off — see
  [ARCHITECTURE.md](ARCHITECTURE.md). Don't wrap `Querier` to "clean" it.
- **Errors** never leak raw. `internal/common/errors.go` defines `DomainError`
  and `MapError`; a service returns a domain error and the handler maps it.

### 2.3 Wiring a slice

`cmd/api/main.go` → `registerModules(app, db, cfg)` does, for each slice:

```go
svc     := feature.NewService(db.Pool, ...deps)
handler := feature.NewHandler(svc)
handler.RegisterRoutes(api)              // api = app.Group("/api/v1")
```

Public endpoints get the rate limiter passed explicitly
(`RegisterPublicRoutes(api, authRateLimit)`); everything else is mounted behind
`auth.RequireAuth`. The limiter is passed per-endpoint rather than as group
middleware on purpose: a Fiber `Group` with middleware would also cover
`/auth/me` and the rest of the API.

### 2.4 Migrations

`backend/migrations/000NN_snake_case.sql`, goose format
(`-- +goose Up` / `-- +goose Down`, with `StatementBegin/End` around anything
multi-statement). Sequential, and **immutable once merged** — a mistake is
fixed with a new migration, never by editing an old one. They run automatically
at boot (`common.RunMigrations`), and `make migrate-up` applies them manually.

## 3. Web (`web/`)

```
web/
├── nuxt.config.ts        # modules, i18n locales, runtimeConfig, inlineStyles
├── server/               # Nitro (BFF) — the ONLY thing that talks to the Go API
│   ├── api/
│   │   ├── auth/*.post.ts        # login, register, google, logout, verify-email…
│   │   │                         #   the only handlers that touch session cookies
│   │   ├── backend/[...path].ts  # authenticated catch-all proxy to the Go API
│   │   └── scryfall/             # server-side calls to third-party APIs
│   ├── plugins/security-headers.ts
│   └── utils/backend.ts          # backendFetch: adds the Bearer, refreshes on 401
├── app/                  # Nuxt srcDir — everything that runs in the browser/SSR
│   ├── pages/            # file-based routing ([id].vue = dynamic segment)
│   ├── components/       # reusable .vue, PascalCase, auto-imported
│   ├── composables/      # useXxx.ts — one per contract slice, auto-imported
│   ├── middleware/       # auth.global.ts (runs everywhere), admin.ts (per-page)
│   ├── layouts/, plugins/, assets/css/, utils/
│   └── types/api.ts      # TypeScript types of the API payloads
├── i18n/
│   ├── i18n.config.ts    # datetime formats per locale
│   └── locales/{es,en,ca}.json
├── shared/types/         # types shared between server/ and app/
└── public/
```

### 3.1 The request path — and why it never shortcuts

```
browser  →  /api/backend/<path>  →  Nitro  →  Go API
             (no token in JS)       (adds Bearer from the httpOnly cookie,
                                     refreshes it transparently on expiry)
```

- `app/composables/useApi.ts` exposes `apiFetch`, which prefixes
  `/api/backend`. A page **never** calls the Go API directly and never sees a
  token.
- The proxy **blocks `auth/*`** (case-insensitively — the Go router is
  case-insensitive, so `/Auth/login` would otherwise slip through). Auth goes
  through the dedicated `server/api/auth/*` handlers, the only ones allowed to
  set cookies.
- A 401 that survives the refresh means the session is gone: `useApi` resets it
  and redirects to `/login`.

### 3.2 Conventions

- One **composable per slice of the contract** (`useFriends`, `useDecks`,
  `useTournaments`…), returning named functions that call `apiFetch` — see
  `app/composables/useFriends.ts` as the reference shape.
- Types for payloads live in `app/types/api.ts`, not inline in the composable.
- Pages are thin: fetching goes through a composable, not raw `$fetch`.
- `middleware/auth.global.ts` gates every route; `middleware/admin.ts` is opt-in
  per page.
- **No hardcoded user-facing strings** — everything goes through `$t()` and all
  three locale files (§5.5).

## 4. Android (`android/`)

```
android/app/src/main/java/com/commandercompanion/
├── CommanderCompanionApp.kt   # @HiltAndroidApp
├── MainActivity.kt
├── core/
│   ├── di/                    # Hilt modules: App, Database, Network, Repository
│   └── util/                  # Resource, ApiError, SingleFlight, QrEncoder
├── data/
│   ├── local/                 # Room: CommanderDatabase, dao/, entity/
│   ├── remote/
│   │   ├── api/               # Retrofit: CommanderApi, AuthApi
│   │   ├── dto/               # wire payloads, kotlinx.serialization
│   │   ├── interceptor/       # AuthInterceptor, AuthAuthenticator (refresh)
│   │   └── ws/                # GameSocketClient + envelopes/events/reconnect
│   ├── repository/            # *RepositoryImpl — decides Room vs. backend
│   └── session/               # SessionManager (DataStore), GoogleAuthClient
├── domain/
│   ├── model/                 # GameSession, PlayerOutcome, Statistics
│   ├── repository/            # the interfaces data/ implements
│   └── usecase/               # LoadStatistics, ResolveGameOutcome, ReplayCommanderDamage
└── presentation/
    ├── navigation/            # Routes.kt (@Serializable type-safe routes),
    │                          #   AppNavigation.kt, SessionViewModel
    ├── screens/<feature>/     # XxxScreen.kt + XxxViewModel.kt (+ XxxState.kt)
    ├── components/, theme/
res/
├── values/strings.xml         # default locale: SPANISH
├── values-en/strings.xml
└── values-ca/strings.xml
```

Dependency direction: `presentation → domain → data`. ViewModels depend on
`domain/` interfaces, which Hilt binds to `data/repository/*Impl` in
`core/di/RepositoryModule.kt`. The deliberate exception is
the whole auth surface — `LoginViewModel`, `RegisterViewModel` and
`SettingsViewModel` inject `AuthApi`/`CommanderApi`/`SessionManager` directly
(see TASKS.md Stage 4).

Naming is strict and mechanical: a feature folder under `screens/` contains
`FeatureScreen.kt` and `FeatureViewModel.kt`; its route is a `@Serializable`
object (no args) or `data class` (with args) in `Routes.kt`; unit tests mirror
the package path under `src/test/`.

**The 2-second rule applies hardest here.** Anything on the in-game path
(`screens/game/`) must stay instant: local Room writes first, network as
best-effort mirroring — never block the UI on the backend.

## 5. Workflows — the exact order

### 5.1 Add or change an API endpoint

1. **[`docs/api/openapi.yaml`](../api/openapi.yaml) first.** Path, params,
   request/response schemas, error codes. Spectral lints it in CI.
2. If it needs new data → do §5.2 first, then come back here.
3. Backend: `query.sql` → `make generate-sql` → `dto.go` → `service.go` →
   `handler.go` (route in `RegisterRoutes`) → wire it in `registerModules` if
   the slice is new.
4. `service_test.go`.
5. Clients that need it: web composable + `types/api.ts`; Android `dto/` +
   `CommanderApi` + repository (+ `domain/repository` interface).
6. `make lint && make test`.
7. Tick the line in [TASKS.md](../roadmap/TASKS.md).
8. `sh .github/scripts/check-architecture.sh` — it verifies steps 1 and 7 actually happened.

### 5.2 Change the database schema

1. **[`docs/database/schema.dbml`](../database/schema.dbml) first.**
2. New migration `backend/migrations/000NN_what_it_does.sql`, with a real
   `-- +goose Down`. Never edit a merged migration.
3. `make migrate-up` locally.
4. `make generate-sql` — the schema change alters the generated models.
5. Regenerate/update [`docs/diagrams/er-diagram.md`](../diagrams/er-diagram.md)
   if relationships changed.

`docs-ci.yml` builds the schema twice in one Postgres — once with goose, once
from the compiled DBML — and diffs `information_schema`. Skipping step 1
fails CI, by design: that check exists because `deck_resync_jobs` went
undocumented for weeks. It compares tables, columns, types and nullability, not
indexes or constraints (DBML can't express partial indexes).

### 5.3 Add a web page

1. `app/pages/<name>.vue` (or `<folder>/[id].vue` for a dynamic route).
2. Data through an existing composable, or a new `useXxx.ts` if it's a new
   contract slice; payload types into `app/types/api.ts`.
3. Strings into **all three** locale files (§5.5).
4. Admin-only? Add `middleware: 'admin'` to the page.
5. `npm run lint && npm run typecheck && npm run build` — the build is what
   catches SSR-only breakage.

### 5.4 Add an Android screen

1. Route in `presentation/navigation/Routes.kt`; register the composable in
   `AppNavigation.kt`.
2. `presentation/screens/<feature>/{FeatureScreen,FeatureViewModel}.kt`.
3. Data through a `domain/repository` interface; implement in
   `data/repository/`, bind it in `core/di/RepositoryModule.kt`. Non-trivial
   logic goes in a `domain/usecase/`, not in the ViewModel.
4. Strings into `values/`, `values-en/`, `values-ca/`.
5. `./gradlew lintDebug testDebugUnitTest`.

### 5.5 Add a user-facing string

| Client | Files | Notes |
|---|---|---|
| Web | `web/i18n/locales/{es,en,ca}.json` | Same key in all three. Missing keys don't fail the page — Vue renders the raw key and returns 200 — so CI checks them. |
| Android | `res/values/`, `res/values-en/`, `res/values-ca/strings.xml` | `values/` is Spanish. A missing key silently falls back to Spanish; use `tools:ignore="MissingTranslation"` for deliberate omissions. |

Both are enforced by `.github/scripts/check-i18n-{web,android}.mjs`, which also
verify that every key referenced in the source actually resolves.

### 5.6 Record a decision

Non-trivial technical choice → `docs/decisions/00NN-kebab-case-title.md`, next
free number, same shape as the existing ones:

```markdown
# ADR-00NN: Title

**Status:** Accepted (YYYY-MM-DD)

## Context
## Decision
## Consequences
```

Link it from [README.md](../../README.md) §8 and from the TASKS.md line it
belongs to.

## 6. Where does this go?

| I want to… | Touch |
|---|---|
| Change an API response | `openapi.yaml` → slice `dto.go` + `handler.go` → clients |
| Add a column | `schema.dbml` → new migration → `make generate-sql` |
| Add business logic | slice `service.go` (or `domain/usecase/` on Android) |
| Add a query | slice `query.sql` → `make generate-sql` (never `query.sql.go`) |
| Change an error's status code | slice `service.go` (`DomainError`) + `common/errors.go` |
| Add a reusable UI piece | `web/app/components/` or `presentation/components/` |
| Call a third-party API from web | `web/server/api/<vendor>/` — server side, never the browser |
| Add an env var | `config/config.go` + `backend/.env.example` (+ `nuxt.config.ts` `runtimeConfig`) |
| Add a CI check | `.github/workflows/` — English name, and update branch protection if required |
| Explain *why* something is the way it is | ADR if it's a decision, `DECISIONS-LOG.md` if it's history |

## 7. Never hand-edit

| Path | Regenerate with |
|---|---|
| `backend/internal/*/query.sql.go`, `querier.go`, `models.go`, `db.go` | `make generate-sql` |
| `web/.nuxt/`, `web/.output/`, `web/package-lock.json` (by hand) | `npm install` / build |
| `android/app/build/`, `android/.gradle/` | Gradle |
| `docs/diagrams/er-diagram.md` (structure) | derived from `schema.dbml` |

CI verifies the first row leaves no diff. If `git status` shows generated files
changing for no reason, check line endings before anything else — see the note
in [`.gitattributes`](../../.gitattributes).

## 9. Guardrails — what stops this document from becoming fiction

Everything above is asserted somewhere, not just written here. Each rule lives
in the tool that can express it natively, and no rule is checked twice:

| Layer | Enforced by | Rule |
|---|---|---|
| Backend | `depguard` in [`backend/.golangci.yml`](../../backend/.golangci.yml) | a `handler.go` must not import a database driver |
| Backend | [`check-architecture.sh`](../../.github/scripts/check-architecture.sh) | no slice touches another slice's `Queries`; SQL only in `query.sql`; handlers map their errors |
| Android | [Konsist tests](../../android/app/src/test/java/com/commandercompanion/architecture/ArchitectureTest.kt) | `domain` free of the framework and of the UI; `data` free of the UI; only the three enumerated auth screens touch Retrofit; every ViewModel is `@HiltViewModel` |
| Web | [`web/eslint.config.mjs`](../../web/eslint.config.mjs) | `app/` and `server/` never import each other; `shared/` stays a leaf |
| Web | [`check-architecture.sh`](../../.github/scripts/check-architecture.sh) | `app/` never reaches the Go API by URL |
| Contract | [`check-architecture.sh`](../../.github/scripts/check-architecture.sh) | every route in `openapi.yaml`, and no path in it that no handler serves |
| Docs | [`check-architecture.sh`](../../.github/scripts/check-architecture.sh) | every document linked from the README hub |

Run them all with `sh .github/scripts/check-architecture.sh`, `make lint`,
`./gradlew testDebugUnitTest` and `npm run lint`.

### How these got here

Two of the Android rules started as **ratchets**, not invariants. When the
Konsist tests were first written, `domain/` imported `data/` in eight files —
its repository interfaces were declared in terms of Retrofit DTOs, and
`GameRepository` returned a Room relation class — and sixteen files under
`presentation/` read DTOs directly. Rather than waive that, the tests froze the
exact set of offending files with a list that could only shrink.

The debt was then paid off in the same session: the payload types moved into
`domain/model/` and `data/` now depends on them, with Room's `GameWithPlayers`
mapped to `PlayedGame` at the boundary (see
[ADR-0019](../decisions/0019-android-domain-owns-its-types.md)). Both lists
emptied, and the ratchets became the plain invariants listed above.

The pattern is worth reusing. A ratchet turns "we know this is wrong" from a
comment nobody re-reads into something the build enforces, without blocking the
work that found it — and when the debt is cleared, the test tells you to tighten
it rather than quietly passing.
