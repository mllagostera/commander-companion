### Auth — email/password
- [x] Password hashing with bcrypt (`internal/users/service.go: RegisterUser`, `bcrypt.GenerateFromPassword`/`CompareHashAndPassword`)
- [x] Real `POST /auth/login`: verifies credentials against the DB (`users.VerifyCredentials`) and issues an access token (JWT HS256) + refresh token
- [x] Real `POST /auth/refresh`: validates the refresh token against `refresh_tokens` (persisted SHA-256 hash, the plaintext token is never stored), **revokes and rotates** it (new refresh token on each use) and issues a new access token
- [x] Real `POST /auth/logout`: revokes the given refresh token (`revoked_at`) in the `refresh_tokens` table
- [x] Real `GET /auth/me`: resolves the user from the `user_id` the middleware left in the context (`common.UserIDKey`)
- [x] Fiber middleware (`auth.RequireAuth`) that validates the Bearer JWT and puts `user_id` into `c.Locals(common.UserIDKey)`
- [x] Middleware applied to all protected routes via the `api.Group("", auth.RequireAuth(...))` group in `main.go`; removed the hardcoded `"dummy-user-id"` values from `decks/handler.go` and `statistics/handler.go` (they now read `common.UserIDKey`)
- [x] Token expiration and signing: **symmetric HS256** with `JWT_SECRET` (env var, insecure default only for dev, justified with `//nolint:gosec`) — decision: RS256 provides no value in a monolith without external token verifiers; TTLs configurable via env (`ACCESS_TOKEN_TTL` default 15m, `REFRESH_TOKEN_TTL` default 720h/30d). Detail and alternatives considered: [ADR-0001](../decisions/0001-auth-jwt-refresh-token-strategy.md)

## Stage 5: Android ↔ Backend Integration

- [x] Authentication interceptor (2026-07-27): `AuthInterceptor` attaches the Bearer access token to the authenticated HTTP client's requests (`NetworkModule`, used by `CommanderApi`); `AuthAuthenticator` intercepts 401s, calls `POST /auth/refresh` once and retries the original request with the new token. Valid for both password and Google sessions (both store the same `TokenResponse` in `SessionManager`). If the refresh fails, `SessionManager` forces a logout (clears DataStore + `clearCredentialState`) and emits an event (`forcedLogoutEvents`) that `AppNavigation`/`SessionViewModel` listen for to return to `LoginRoute` from any screen. Design note: `AuthApi` (login/google/refresh/logout) deliberately uses an OkHttp client *without* this interceptor — those endpoints are public (`security: []` in the spec) and reusing the authenticated client for the refresh itself would cause recursion
- [x] Session persistence with DataStore (2026-07-27): `SessionManager` (`data/session/SessionManager.kt`) stores the access token, refresh token and expiry (`androidx.datastore:datastore-preferences`, added to `app/build.gradle.kts`)
- [x] **Best-effort mirroring of the local seat against the real backend** (2026-07-27, explicit seat/deck selection added 2026-07-28): `GameRepository.bootstrapRemoteGame(deckId)` — on creating a game, `POST /games` + `POST /games/{id}/join` with the deck the user chose in `PlayerSetupScreen` for the seat marked "That's me" + an attempted `POST /games/{id}/start` (409 = "not 2 players yet," not an error, the session stays `PENDING`); `GameViewModel.mirrorLifeChange` mirrors every life change of the local seat via `POST /games/{id}/actions` (`LifeChange`, no `target_id`) while the session is `active`; `finishRemoteGame` fires `POST /games/{id}/finish` on ending. ## Stage 6: Synchronization (WebSocket)

- [x] Message protocol design (which `game_actions` events are broadcast live and their format) — [ADR-0005](../decisions/0005-websocket-protocol.md): broadcasts the 7 `game_actions` actions unfiltered (same `GameActionResponse` DTO already used by REST) + a `game_finished` lifecycle event; over a common JSON envelope (`type`/`game_id`/`actor_id`/`payload`/`timestamp`); authentication via an `{"type":"auth","token":"..."}` message as the first frame after connecting (not a JWT query param, to avoid leaking it in Fiber's access logs; no subprotocol, given the semantically incorrect use of that field).
