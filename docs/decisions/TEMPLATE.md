## Context

What situation forced a decision. The constraints that were real at the time
(deadline, existing stack, something that broke). Written so a session six
months from now understands *why this was even a question* without reading the
git history.

## Decision

What was decided, stated plainly. If several options were weighed, name them and
say why the others lost — an ADR whose alternatives section is empty is usually
an ADR nobody actually decided.

## Consequences

What this makes easy, what it makes hard, and what it forecloses. Include the
known limits explicitly: the thing that will break first, the scale at which
this stops working, the follow-up task this leaves open. A consequence you knew
about and wrote down is a decision; the same one discovered later is a bug.
